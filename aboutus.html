Building this website

My content theme was a restaurant. I designed Tamarind Table, a fictional Hyderabadi kitchen in Tampa, around three real tasks: a guest finding a dish that fits their diet, a staff member keeping the menu current, and an owner deciding what to promote and when to staff up.

  1. Planned the data first. Each menu item has a name, category, price, description, spice level, dietary flags, availability and monthly portions sold. Every page reads from this one model, so the static version maps directly onto a future database table.
  2. Built the layout in plain HTML and CSS. One shared stylesheet with CSS variables for color, type and spacing keeps all four pages consistent, and CSS Grid with two breakpoints makes them work from phone to desktop.
  3. Added JavaScript where it helps the user. The home page filters the menu by category, diet and search. The Manage Menu page mocks Create, Read, Update and Delete with form validation, and saves changes in localStorage so they carry over to the other pages.
  4. Visualized the data with Chart.js. The Analytics page shows revenue trend, sales by category, best sellers and busiest days. Two of the charts are computed from the live menu, so editing a dish updates them.
  5. Tuned for speed and access. No CSS framework, scripts deferred, Chart.js loaded only on the page that needs it, the logo is a sub-1 KB SVG, and all of the site's own HTML, CSS and JavaScript adds up to about 60 KB. Every page has a skip link, labeled form fields and visible keyboard focus.

The hardest part was keeping the CRUD form simple while still catching mistakes: it rejects empty names, out-of-range prices and duplicate dishes, and escapes text before showing it so typed input can never inject HTML.
